# Amidst-GTNH v0.3.3

本版修复主世界 Village Names 村庄候选的间距、群系准入和原点禁生成半径，
减少错误标记与漏标。发行版本 **0.3.3**，通信协议仍为 **25**。

## 本版更新

- 按实际生效的村庄生成器读取间距。Village Names 使用实例参数和运行时配置，
  原版 RWG 保留自己的地形准入规则。
- Village Names 使用区块中心的最终群系名称匹配允许名单，并应用原点禁生成半径。
- 准确性报告使用独立群系预测，避免拿已加载数据与自身比较。
- 保留生成器参数适配与原生 JAR 对照工具，供后续版本核验；未知生成器明确报错。

村庄标记仍代表候选起始区块，无法保证建筑已经生成或组装有效。
规则、参考版本及对照结果见[村庄定位](reference/village-prediction.md)。
v0.3.2 的生物群系配色和要塞图标更新继续保留；月球村庄算法未改动。

## 安装

1. 解压 `Amidst-GTNH-v0.3.3.zip` 到独立目录。
2. 关闭 GTNH，移除旧 Worker，将 `amidst-gtnh-worker-v0.3.3.jar` 放入 `mods`，只保留一份。
3. 重启游戏，使用 Java 17 或更新版本运行 `run-viewer.bat`。Viewer JAR 不放入 `mods`。

参考环境沿用 GTNH 2.9.0-beta-3，其他整合包版本尚未完成兼容性验证。请使用包内配套两端。
群系缓存保存群系 ID，结构候选不持久缓存；升级后无需删除群系缓存。

## 已知限制

- 村庄起点记录不等于有效建筑；当前准确性报告尚未区分 `Valid=false` 的村庄记录。
- 要塞地图与“前往要塞”菜单仍使用不同预测线路；标记不是传送门房间，详见[要塞定位](reference/stronghold-prediction.md)。
- 纯种子出生点仍为估算；结构、矿脉和小行星标记代表候选，无法保证实际存在。
- 地图缓存仍需连接 Worker；部分末地查询依赖已加载存档状态。

## 验证与交付

发布构建运行 Viewer、Worker 测试及 RWG / GregTech 参考算法对照，
检查两端版本、协议、共享数据类及 Worker SRG 映射。测试计数见包内 `build-info.json`。

这些检查证明所测输入的选点一致，不能视为完整游戏中的建筑准确率。
