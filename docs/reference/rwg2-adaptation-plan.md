# RWG2 实现与精度边界

本文说明 **v0.4.0 正式版 / 协议 31** 的实现，参考环境为 GTNH 2.9.0 的 RWG2 2.0.6。
安装与功能清单见[发布说明](../release-v0.4.0.md)，历次试验、微基准、配置指纹和早期方案
保留在[开发历史](../archive/rwg2-development-history.md)。历史中的内部试用编号不代表正式发布顺序。

## 生成器与群系

- `OverworldGenerator` 识别 `RWG2_CONTINENTS`（界面 RWG2 Smooth）和 `RWG`（RWG-Alpha）。
  协议省略生成器时沿用旧 RWG；不接受普通 `RWG2` 世界类型。新建种子、世界类型切换和筛种器使用一致选择。
- 每张地图绑定不可变的生成器选择；缓存包含种子、生成器、噪声模式与实际会话身份。
  已加载群系证据只用于种子和世界类型匹配的存档。
- `StoredBiomeAccess` 使用 EndlessIDs 的扩展存储接口；`DisplayBiomeIds` 与 Viewer 的整型群系栅格
  不截断到 8 位，不修改整合包原有群系注册或配置。
- `Rwg2Runtime` 核对管理器与生成器字节码，构造独立种子上下文，重放最终群系写入顺序。
  只使用临时数组与预览世界，不调用真实区块生成、加载、装饰或 Forge 地表事件。

先前本地配置核对记录包括：大陆宽度 2700、平均／最小海洋宽度 100／50、海洋比例近似上限 0.4，
岛屿宽度 300–600。完整配置表与文件指纹见开发历史。这些值是参考输入，不能写成算法常量；
Worker 使用实际生效的模组配置，配置变更后需要重启游戏。

## 精细采样与调度

Viewer 每个 512×512 格瓦片读取每 4 格的最终群系，不使用粗预览或 Viewer 边界插值。
`Rwg2BiomeCache` 复用混合输入；纯海洋路径先核对原生条件，海岸、岛屿和特殊地形继续完整重放。
`Rwg2MountainInfluence` 与 `Rwg2JunctionStrength` 复用邻域几何和噪声，保留原生浮点计算结果与采样密度。

`Rwg2ParallelSupport` 核验 237 个 RWG2 2.0.6 类资源及已注册回调。
通过核验的 `Rwg2SamplingPool` 在游戏线程初始化上下文，再将纯算术移至后台；每个任务独占管理器、
噪声、随机数、地形数组和可变缓存。未知回调保留游戏线程路径，真实世界证据始终在游戏线程读取。

底图请求最高 64 路，Worker 默认上限为逻辑处理器数减 2，最少 1、最多 64。
上下文最多为实际计算线程数加两个后继，超量请求等待资源，不反复在游戏线程轮询。
取消中的任务退出前不得复用上下文；空闲计算线程五秒后退出，有界上下文缓存留待复用。

Viewer 发布完整精细底图快照，结构完成后补齐标记；不会混入上一轮失效结果。
局部区块变化只刷新所属瓦片和结构查询邻域，出生点变化只刷新旧、新出生点附近。
底图与结构分别限流。底图加载期间一个结构请求，底图完成后立即扩展至最多四个；再次拖动可直接恢复底图。

`MapStorage` 的写入与容量维护使用独立后台队列，最多等待 64 项。
队列满时跳过可选磁盘保存，已收到的瓦片照常发布；目录排序不再反复读取文件属性。
保留 CRC、整体文件替换与 Worker 最新缓存标识校验。

## 结构与开关

| 类型 | 预测来源及边界 |
| --- | --- |
| 村庄、矿井、要塞 | 当前 RWG2 配置与独立生成器规则；村庄识别最终生效的 Village Names 参数 |
| Roguelike、普通 LootGames、史莱姆岛、AE2 | 现有独立模组预测；候选不等于实际建筑已经存在 |
| 海底神殿 | 已核验的 Village Names 选点与周边群系检查 |
| 暮色门／河道小游戏 | 原生河道洞室定位与哈希选择，分别标示 Y=64／Y=66 |
| 下界门／熔岩小游戏 | 原生熔岩洞室定位与哈希选择，Y=39，并排除火山范围 |
| 刷怪笼地牢 | 独立洞穴重放，仍受装饰及邻近结构影响 |
| Thaumcraft 节点／祭坛 | 保留同一随机序列的必要前序计算 |

`StructureQuerySelection` 只在当前地图加载作用域中传递开启类型，不污染独立导出或准确性验证。
Worker 的可选 `structureTypes` 在算法入口筛选；缺省保留全量查询，空集合不请求任何标准结构。
选择性缓存将类型纳入键，RWG2 候选缓存记录已计算的熔岩、河道和神殿部分，重新开启时补查。

暮色门与河道小游戏都关闭后跳过河道 POI 定位，下界门与熔岩小游戏同理。
只开启普通 LootGames 不会连带扫描这两类洞室。隐藏暮色门不改变原生选择，不能将它重新判为小游戏。
底图自身所需的原生河道规则不受这些开关影响。

`Rwg2PoiPool` 使用最多四个独占计算上下文，并受 Viewer 设置与逻辑核数减 2 的上限约束。
额外最多准备一个后继；初始化和已加载方块证据留在游戏线程。
未知洞穴替换器保留游戏线程路径。已加载证据不能缓存为永久存在性结论。

## 出生点、资源与显示

RWG2 任意种子使用本模式地表和原生游走估算出生点，匹配存档时优先返回记录。
未知结果不伪造原点；估算不覆盖第三方事件／装饰的全部影响。详见[出生点维护](spawn-prediction.md)。

矿脉和流体使用 512×512 格查询瓦片、最多两个请求，并沿用游戏线程内的分段任务。
切换图层与移出视野取消无关工作。群系颜色和传送门图标只影响显示，不改变采样或生成规则。

## 验证依据

`InstalledRwg2ReferenceTest` 使用本地 RWG2 2.0.6 JAR，对照最终群系、地下数组、噪声状态隔离、
原生交汇强度与洞室中心。覆盖 Perlin／OpenSimplex、正负坐标、扩展 ID 与并行独占上下文。
`InstalledRwgReferenceTest` 保留旧 RWG 对照；参考 JAR 和 MCP 映射由开发者提供，不随源码包分发。

回归同时覆盖关闭类型时不调用相关定位器、过滤变化与失效补查、单请求额度下底图和结构独立、
取消任务、过期快照拒绝发布、四路原生地下重放与串行一致。命令见[构建说明](../../BUILDING.md)。

这些测试不等同于所有模组组合下的完整世界生成。用户已确认本地筛种速度达到预期；
发布打包不替代不同存档、维度与配置的完整游戏验收。精度与性能的原始测量条件保留在开发历史。
