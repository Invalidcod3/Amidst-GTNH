# RWG2 版本选择与网页端／Wiki 同步说明

## 桌面端行为

| 实际加载的 RWG2 | 默认 Smooth 名称 | 对应整包 |
| --- | --- | --- |
| 2.0.6 | RWG2 Smooth (GTNH 2.9.0) | GTNH 2.9.0 |
| 2.0.9 | RWG2 Smooth (GTNH 2.9.1) | GTNH 2.9.1 |
| 旧 Worker 没有版本信息 | RWG2 Smooth | 不推断整包版本 |

桌面端依靠游戏实际加载的模组和配置计算，不内置两套可随意切换的完整世界生成器。每次连接只显示当前实例支持的 Smooth 版本；RWG-Alpha 继续作为另一项。重新连接不同实例时，Smooth 默认设置随当前版本更新。显式请求另一版的世界类型会被拒绝，避免标签与算法不一致。

Worker 根据原始 `ChunkManagerRealistic` 字节码签名选定完整审计清单，握手可选字段 `rwg2Version` 返回 `2.0.6` 或 `2.0.9`。这是原生构建信息，不是读取启动器文件夹名。后续采样仍核验相应原生类，单个握手字段不能绕过校验。

两种 Smooth 的请求字段仍为 `generator: "RWG2_CONTINENTS"`，Alpha 为 `"RWG"`；协议保持 31。Viewer 保留旧 `RWG2 Smooth` 名称与 `RWG2_CONTINENTS` 的解析，缺失版本字段时不影响旧协议连接。缓存身份已包含模组、配置及世界上下文；更换生成环境不会共用预测瓦片。

## 独立网页端和 Wiki 的后续工作

网页端及 ChunkbaseNH-Wiki 是单独项目，本次按用户安排留待后续同步。以下是移植清单，不代表它们已经支持 2.9.1。

已检查的 Wiki 内置包为 `rwg2-smooth-2.0.6`，编译入口 `tools/compile-rwg2.py` 固定核验 2.0.6 源码和参考 JAR；界面“2.9.0+ 默认”的描述不能作为 2.9.1 支持依据。离线网页没有游戏握手，应提供显式版本选择，并将其关联到独立的算法包；仅修改名称或复制旧包不足以支持 2.9.1。

建议保留现有 2.0.6 包及其参考样本，另生成 2.0.9 包。原有 `rwg2-smooth` 分享链接和存储设置应继续明确指向旧版，或经过一次显式迁移；不能悄悄解释成新版。分享链接、本地存储、工作线程请求、缓存键及 GPU 校验缓存均需包含算法版本。对不支持的版本明确报错，避免回退到另一版后仍显示原标签。

2.0.9 的移植范围：

- `ContinentalConfig.biomeSizeMultiplier`、气候带及其宽度／混合／漂移配置、群系与大陆偏移、每大陆污染之地规则。污染之地需从小群系池副本移除，不改共享池。
- `SettingsConfig` 取代旧 `ConfigRWG` 的生成设置；继续区分 Perlin 与 OpenSimplex。
- 河流雕刻的新回调接口、水面判定、熔岩洞室修正；不能沿用只匹配 2.0.6 方法体的文本裁剪规则。
- `RiverJunctionLandmark` 的中心归属、20 区块范围去重、概率、距世界原点的最小距离和未激活水池分支。
- 未激活水池使用蒲公英，已激活传送门用虞美人，共用原有图层。桌面协议子类型为 `RWG2_RIVER_CHAMBER_UNLIT`，结构种类仍是 `RWG2_TWILIGHT_PORTAL`。

植物目录的 150 个条目在 2.9.0／2.9.1 默认配置下具有相同群系准入规则，可共用目录；地形中这些群系的位置仍必须按所选版本计算。植被选择只负责自动勾选匹配群系并开启高亮，保留完整群系列表与既有按钮。

## 验证依据

详细来源、原生类及配置差异见 [GTNH 2.9.1 适配记录](gtnh-2.9.1.md)。移植后应分别与 2.0.6 和 2.0.9 原生 JAR 对照最终群系、地形／地下结构、出生点及河流地标；新版另覆盖缩放、气候带、偏移和污染之地设置。

同一种子、坐标在版本切换后的结果应来自相应独立包，并验证分享链接往返、旧链接语义、快速切换中的过期任务取消、缓存隔离、CPU 与 GPU 一致性。桌面端通过原生对照不能代替网页编译产物的验证。
