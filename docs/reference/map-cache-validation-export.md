# 地图缓存、准确性验证与向外导出

当前安装与协议要求见[发布说明](../release-v0.3.1.md)。

## 地图缓存与恢复

「设置」中的「将生物群系地图缓存到磁盘」「恢复上次地图视图」默认开启，可分别关闭。

- 生物群系地图保存在用户目录 `.amidst-gtnh/biomes`，容量约 256 MiB；按批次清理旧数据。
- 视图保存在 `.amidst-gtnh/views`，约每 5 秒及正常关闭时保存中心坐标、缩放、维度、资源标记模式及筛选条件。
- 缓存按种子、存档路径、世界类型、模组版本/文件、配置、维度和采样区域区分；复用前还核对当前已加载群系数据。
- 校验失败、文件损坏或目录不可写时退回正常查询。关闭缓存不删除已有文件。
- 冷启动时，模组与配置指纹在独立后台线程中准备；准备期间直接查询瓦片，不占用游戏线程或 Worker 连接线程等待文件扫描。准备失败后间隔 30 秒重试。
- Viewer 的可选缓存查询最多等待 2 秒；失败或超时后直接查询瓦片，并暂停缓存查询 30 秒。地图的正常请求保留原超时时间。已有缓存文件无需删除。
- 此缓存用于减少重复计算，仍需连接游戏核对数据；不提供离线地图浏览。

同种子不同存档分开保存。结构和矿脉的实际判断不写入持久地图缓存。切换存档后会清除结构及资源显示缓存；已在途的旧结构回复不能重新写回缓存。没有实际生成证据的候选地牢不会被永久排除。

「世界 → 刷新地图及结构判断」可主动更新显示。主世界区块变化也会使相关判断重新查询。

## 准确性验证

打开「世界 → 准确性验证」，使用当前地图维度，填写左上角 X/Z、区域宽高，以及生物群系采样间距。可同时勾选生物群系、结构、矿脉。

区域最大 512 × 512 方块，生物群系最多 16384 个采样点。先在游戏中进入匹配种子的存档并加载目标维度。验证仅检查当前可读的数据，不主动生成或加载区块。

| 类别 | 比对内容 | 限制 |
| --- | --- | --- |
| 生物群系 | 独立预测与已加载区块保存的群系编号；转换到各维度的预览编号 | 未加载区块、未保存编号为无法验证；末地等虚拟地形分类不能直接用群系编号验证 |
| 结构 | 主世界村庄、废弃矿井、要塞的预测起始区块与存档生成记录，双向检查遗漏 | 检查生成起点，不逐方块确认建筑完整性；周边未完成地物生成或缺少记录时为无法验证；其他模组缺少可靠记录的结构保留为无法验证 |
| 矿脉 | 独立种子预测与 Visual Prospecting 记录的矿脉种类及中心 | 无记录为无法验证；明确的无矿脉记录可以比较；不逐方块检查矿石数量、开采情况或具体高度 |

Roguelike Dungeon 另调用模组的只读选址检查，通过受限的世界读取接口查看当前已完成地物生成的区块。报告显示当前地形通过、未通过或暂不可检查，但三种情况都不视为地牢存在性的最终证明。生成后的建筑本身也可能改变选址条件。检查结果仅属于这次存档状态，重新验证会重新读取；不会生成地牢或写入排除名单。

报告分别统计一致、差异、无法验证。一致率 = 一致 ÷（一致 + 差异），无法验证不计入分母。没有可比较样本时显示横线。各类别最多保留 1000 条明细，优先保留差异；总计仍包含全部样本。可保存 JSON 或 CSV，包含种子、实际维度 ID、存档会话、时间、区域、统计和明细。验证中切换存档会中止本次报告，避免混用证据。

## 从起始点由近至远导出

打开「世界 → 导出坐标」，勾选「从起始点由近至远导出」，填写起始 X/Z 和坐标数量（1–10000）。沿用结构、矿脉、流体类型和筛选条件，可导出 CSV、JourneyMap 文件，或直接导入游戏。

按同一维度内的方块 X/Z 平面直线距离排序，而不是地图区域扫描顺序。检查完可能包含更近结果的区域后，才计入一个坐标；同距离按 X、Z 稳定排序，相同 X/Z 去重。达到数量后停止，可取消。

搜索最多检查 65536 个 512 方块区域；若范围内数量不足，会提示并仅导出已经确认距离顺序的结果。直接导入游戏沿用 2000 个路径点的上限。坐标输入改为清楚的 X、Z 标签，移除了外侧方括号。

## 验证范围

自动化检查包含距离排序与全量排序结果比较、负坐标/边界/同距离/取消、缓存校验及恢复、独立群系预测、缺失证据、结构重新验证、同种子存档切换，以及旧空回复的缓存竞争。构建同时检查 Viewer 和 Worker；这些检查不替代用户具体存档中的实际精度报告。
