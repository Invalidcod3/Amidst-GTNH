# 使用说明

安装见 [项目说明](../README.md)，v0.4.0 更新见 [发布说明](release-v0.4.0.md)，算法边界见 [RWG2 实现记录](reference/rwg2-adaptation-plan.md)。

## 启动与地图

- 启动 GTNH 到主菜单即可查询支持独立预测的维度。可以先开 Viewer，连接成功后会自动加载地图。
- Worker 首次启动默认启用；已有配置中主动设置的 `enabled=false` 会保留。
- 在“设置 > 语言”切换简体中文或 English；在“图层”中选择维度、结构、矿脉或流体。
- 支持已加载数据的查询会优先使用游戏记录。纯种子预览和未生成区域显示预测；末地部分矿脉查询需要先进入对应存档的末地。
- 出生点区分“存档世界出生点”和“估算世界出生点”。尚未取得结果时不伪造 `(0,0)`；玩家首次进入位置可能与世界出生点不同。


LootGames 在图层菜单中分为三项，可独立开关：普通地牢沿用原图标，RWG2 熔岩洞室使用橙色边框（Y=39），RWG2 河道洞室使用青色边框（Y=66）。两类洞室也可分别导出坐标，均沿用已有 Worker 预测结果，不额外采样。注意：本地 RWG2 2.0.6 的熔岩洞室装饰明确避开火山范围，不能用小游戏标记代替火山定位。火山的岩浆室是另一种地形。

Phantasmagoric Inferno 的底图色为殷红 `#9D2038`，Tainted Land 为紫黑 `#30203F`。

大视野下的临时超时、空响应或断开的响应会自动重试，繁忙时降低实际请求并发，正常响应后逐步恢复；用户设置的线程数上限不变。移出视野、关闭窗口或关闭图层可取消等待。真实协议、身份验证及算法错误仍明确报错；JourneyMap 写入遇到通信异常不自动重发，避免重复操作。Worker 会清理断开的请求，并在连接队列满时要求稍后重试。请使用 v0.4.0 正式版的配套 Worker，并在替换后重启游戏。


游戏区块加载／卸载现在只刷新相应瓦片及一圈结构查询邻域，重复通知合并；不会因此中断远处瓦片或清空全部结构缓存。仍采用精细采样，刷新已有画面不再重新淡入；RWG2 底图先显示、结构随后补齐，各次发布均使用完整快照。世界状态变化造成的过期采样会短暂等待后重试，不触发拥堵降速；真正繁忙、切换维度或主动刷新仍按原有规则处理。

首屏现在按需分配瓦片缓冲，避免在界面线程一次创建 1024 块；首次状态检查读取已知区块变化，不再无条件整屏重算。Worker 只准备实际线程数加最多两个后继任务的采样器，其余请求等空闲资源后继续。精细采样步长和最大 64 线程设置不变。

海岸和河流交汇区域仍执行完整地形规则；新增优化复用固定邻域几何数据，减少每个区块中重复的山地邻域扫描，未降低采样精度。首次底图与已选结构的计算仍需时间，实际等待取决于区域、图层和机器负载。

## RWG2 与旧 RWG

GTNH 模式的新建种子窗口使用“RWG2 Smooth / RWG-Alpha”世界类型列表；本地 2.9.0 默认首项为 RWG2 Smooth。前者对应 `RWG2_CONTINENTS` 大陆模式，后者对应旧 `RWG`。
“世界 → 世界类型”可保留种子切换预览；“设置 → 默认世界类型”用于后续新建地图，原版模式有独立设置。打开存档时读取存档自身的生成类型。

切换仅影响 Amidst 预览。RWG2 已开放海底神殿、自然暮色门／下界门、洞室与普通 LootGames、史莱姆岛、AE2 陨石图层。自然暮色门使用虞美人图标，下界门使用紫色传送门图标。洞室标记区分熔岩洞室（小游戏／下界门 Y=39）和河道洞室（暮色门 Y=64、小游戏 Y=66）；未获得已加载区块方块证据的标记显示“地形候选，待核验”。河道候选还受实际水位与空气条件影响。村庄、要塞、矿井、Roguelike、Thaumcraft 与原版刷怪笼地牢候选图层已接入；地牢仍受湖泊、邻近结构和模组装饰影响，不保证每个候选最终生成。任意种子的 RWG2 出生点估算已接入，匹配存档时优先显示记录出生点；估算不包含第三方地形事件和装饰对地表的全部改动。

底图修正了海洋与红树林等混合标签群系的颜色。Tropics 使用绿色，Jungle 与 Jungle Mesa 使用棕绿色，Jungle Canyon 使用灰绿色；Oasis 与 Lush Desert 分为鲜绿和沙黄绿，Cold Forest 等使用偏冷的针叶林配色；已知海洋类型使用蓝／青色。自定义配色文件仍有优先权。纯海洋瓦片会在核对原生采样条件后跳过无关方块构造，海岸和岛屿继续完整重放。

RWG2 每个 512×512 格瓦片先显示每 4 格采样的精细底图，结构结果随后补齐。洞穴查询使用独立通道，底图仍在加载时最多一个结构请求；底图完成后立即按线程设置扩展到最多四个结构请求，无需等待底图线程退出。等待洞穴时不占用底图请求槽，即使只设置一个底图线程也能加载其他瓦片。底图与结构工作线程空闲约五秒后退出，采样上下文保留有界缓存供下次复用。每次发布使用完整显示快照，不混入上一轮已失效的结构图标。矿脉／流体仍单独加载。河流洞室保留原生 2 格候选扫描和中心搜索，优化轴向噪声、Voronoi 特征点和距离运算，没有扩大采样间隔。已移除粗预览；河流、海岸与群系边界仍由 Worker 的原生算法判定。RWG2 精细底图的原生计算已移到独立后台线程，每个任务独占噪声生成器、随机数、数组和缓存。游戏线程负责初始化采样器和核对已加载区块记录，后台计算等待期间会停放请求，不消耗游戏线程预算。移出视野的未完成请求可取消，已完成的精细图仍可复用。

在“设置 → 线程数”调整并按原有提示重启 Viewer 后，RWG2 底图请求和后台计算的目标并发都会随之调整；Viewer 最高 64。Worker 默认计算上限为 `max(1, 逻辑处理器数 − 2)`，最多 64，实际并发取设置值与 Worker 上限中的较小值。可在整合包 JVM 参数中用 `-Dgtnh.amidst.worker.rwg2Threads=12` 指定 Worker 上限，需重启游戏。增加计算线程也会增加独立缓存的内存占用。旧 RWG 和其他维度请求仍最多 4，RWG2 结构请求为 1–4 路，Worker 的独立洞穴计算最多 `min(4, 线程设置, max(1, 逻辑处理器数 − 2))` 路；资源图层仍最多 2。

矿脉／流体使用 512×512 格查询瓦片，最多两个请求并行，从视野中央向外加载；切换图层和离开视野会取消无关请求。过度缩小时仍会提示放大地图，提示位于左下性能信息上方。矿脉／流体查询沿用游戏线程内的分段任务；此次后台并行针对 RWG2 精细底图。

关闭图层会取消当前过期查询，并在后续请求中省略关闭的结构类型。暮色门与河道小游戏都关闭后，跳过河道洞室定位；下界门与熔岩洞室小游戏都关闭后，跳过熔岩洞室标记预测。只开启普通 LootGames 不会顺带扫描这两类洞室。村庄、矿井、要塞、Roguelike、AE2 等也按选择进入对应算法。刷怪笼地牢有独立请求，关闭后不做洞穴重放。Thaumcraft 灵气节点与祭坛共用随机序列，保留已开启项所必需的前序计算；两项都关闭则不查询。

这些开关影响结构预测，不改变精细底图所需的原生地形规则。同一洞室类型仍有任一结构开启时，共享定位仍需执行；关闭项不再做方块证据核查。缓存区分图层选择，重新开启图层会补查，导出／准确性验证不受地图隐藏设置影响。

## 地图缓存与恢复

“设置”中的磁盘群系缓存和视图恢复默认开启，可分别关闭。视图包含地图中心、缩放、维度和筛选条件。
缓存按存档、种子、配置等输入区分；损坏、无法写入或准备超时时直接查询地图。
缓存写入和容量清理使用独立后台线程；队列满时仅跳过本次磁盘保存，已收到的瓦片照常显示。清理时每个文件只读取一次属性，缓存读取也不再等待清理锁。旧缓存格式兼容，无需删除已有文件。
缓存仍需连接 Worker 核对数据，不提供离线浏览。结构与矿脉判断不作为永久记录写入地图缓存。
切换存档或手动刷新后，地牢选址会重新检查。

## 准确性验证

在“世界”菜单选择验证入口，指定区域，对比生物群系、结构和矿脉，并导出 JSON/CSV。
报告分别记录一致、不一致和无法验证；缺少实际证据不算正确，也不算不存在。
检查只使用已有数据，不主动生成区块。小行星候选不具备普通矿脉记录时保留“无法验证”。

## 坐标导出与 JourneyMap

- 在“世界 > 导出坐标”中选择类型、范围和筛选条件。
- 向外导出填写起始点 X/Z 和数量；按平面距离由近到远选取，达到数量停止。达到查询上限时可能不足指定数量。
- “设置 > 双击路径点自动添加到 JourneyMap”默认关闭。启用后，双击标记会添加到当前游戏世界，需要已进入存档。
- 导入使用所选维度的真实 ID 和该维度 X/Z，下界坐标不重复缩放。已知的小行星中心高度会保留，未知高度使用导航默认值，不能当作实测地表高度。
- 小行星标点代表生成中心候选；矿脉标记不保证实际存在矿石。流体 L/Op 是单次操作产出，不是总储量。

## 连接与排障

1. 核对两端均来自当前发布包，`mods` 中没有重复 Worker，替换后已重启游戏。
2. 核对 `config/amidstgtnhworker.cfg` 的启用状态，以及两端端口、口令是否一致。Worker 默认只监听本机回环地址。
3. 等待游戏完成加载；缓存准备不会阻止瓦片正常查询。不必为排障先删除全部缓存。
4. 查看 Viewer JAR 旁的 `viewer.log`；目录不可写时改写到用户目录的 `amidst-viewer.log`。Worker 错误在游戏日志中。
5. 报告问题时提供两端版本、日志相关段落、种子、维度、坐标、是否加载存档，以及复现步骤；不要公开口令或完整私人存档。

双击 Viewer JAR 自动打开的控制台会随 Viewer 关闭。由已有终端启动时，日志留在该终端。
命令行可传 `-gtnh-worker-port`、`-gtnh-worker-token` 和 `-log`；旧 `-gtnh-worker` 参数仍兼容。
原版 Amidst profile 模式需显式使用 `-vanilla`。更详细的历史排障证据保存在[归档](archive/worker-troubleshooting.md)。
