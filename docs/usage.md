# 使用说明

安装和版本要求见 [当前发布说明](release-v0.3.1.md)。

## 启动与地图

- 启动 GTNH 到主菜单即可查询支持独立预测的维度。可以先开 Viewer，连接成功后会自动加载地图。
- Worker 首次启动默认启用；已有配置中主动设置的 `enabled=false` 会保留。
- 在“设置 > 语言”切换简体中文或 English；在“图层”中选择维度、结构、矿脉或流体。
- 支持已加载数据的查询会优先使用游戏记录。纯种子预览和未生成区域显示预测；末地部分矿脉查询需要先进入对应存档的末地。
- 出生点区分“存档世界出生点”和“估算世界出生点”。尚未取得结果时不伪造 `(0,0)`；玩家首次进入位置可能与世界出生点不同。

## 地图缓存与恢复

“设置”中的磁盘群系缓存和视图恢复默认开启，可分别关闭。视图包含地图中心、缩放、维度和筛选条件。
缓存按存档、种子、配置等输入区分；损坏、无法写入或准备超时时直接查询地图。
缓存仍需连接 Worker 核对数据，不提供离线浏览。结构与矿脉判断不作为永久记录写入地图缓存。
切换存档或手动刷新后，地牢选址会重新检查。

## 准确性验证

在“世界”菜单选择验证入口，指定区域，对比生物群系、结构和矿脉，并导出 JSON/CSV。
报告分别记录一致、不一致和无法验证；缺少实际证据不算正确，也不算不存在。
检查只使用已有数据，不主动生成区块。小行星候选不具备普通矿脉记录时保留“无法验证”。

## 坐标导出与 JourneyMap

- 在“世界 > 导出坐标”中选择类型、范围和筛选条件。
- 向外导出填写起始点 X/Z 和数量；按平面距离由近到远选取，达到数量停止。达到查询上限时可能不足指定数量。
- “设置 > 双击路径点自动添加到 JourneyMap”默认关闭。启用后，双击标记会添加到当前游戏世界，需要已进入存档。
- 导入使用所选维度的真实 ID 和该维度 X/Z，下界坐标不重复缩放。已知的小行星中心高度会保留，未知高度使用导航默认值，不能当作实测地表高度。
- 小行星标点代表生成中心候选；矿脉标记不保证实际存在矿石。流体 L/Op 是单次操作产出，不是总储量。

## 连接与排障

1. 核对两端均来自当前发布包，`mods` 中没有重复 Worker，替换后已重启游戏。
2. 核对 `config/amidstgtnhworker.cfg` 的启用状态，以及两端端口、口令是否一致。Worker 默认只监听本机回环地址。
3. 等待游戏完成加载；缓存准备不会阻止瓦片正常查询。不必为排障先删除全部缓存。
4. 查看 Viewer JAR 旁的 `viewer.log`；目录不可写时改写到用户目录的 `amidst-viewer.log`。Worker 错误在游戏日志中。
5. 报告问题时提供两端版本、日志相关段落、种子、维度、坐标、是否加载存档，以及复现步骤；不要公开口令或完整私人存档。

双击 Viewer JAR 自动打开的控制台会随 Viewer 关闭。由已有终端启动时，日志留在该终端。
命令行可传 `-gtnh-worker-port`、`-gtnh-worker-token` 和 `-log`；旧 `-gtnh-worker` 参数仍兼容。
原版 Amidst profile 模式需显式使用 `-vanilla`。更详细的历史排障证据保存在[归档](archive/worker-troubleshooting.md)。
