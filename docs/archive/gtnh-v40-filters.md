# v40：探矿下拉选择和流体最低产出筛选

> 历史记录：安装要求、协议号及验证结论属于当时版本。当前状态见[发布说明](../release-v0.3.1.md)。

更新配套 Viewer 与 Worker 后，打开 `Layers → Markers → Ores / Fluid`，
再选择 `Filter Ores / Filter Fluid`。

- **Ore vein / Fluid**：不可手填的下拉框，列出当前维度注册的矿脉或流体。
  选择 `All ore veins / All fluids` 恢复全部。矿脉列表来自 Visual Prospecting 的运行时目录，
  流体列表来自 GregTech 当前维度的地下流体配置，与地图有没有加载某一片区域无关。
  显示模组提供的名称，内部按完整注册 ID 匹配；同名条目附带 ID 区分。
  矿脉选择框的悬停提示显示其组成矿物。
- **Minimum L/Op**：流体筛选的最低产出，接受非负整数。默认 `0` 不限制；
  例如 `150` 保留每次操作产出大于或等于 150 L 的区块，隐藏其余区块。
  同一流体田允许只留下部分区块；所有区块都低于阈值时整片流体田隐藏。
  筛选在远近缩放下都生效，具体区块数值仍只在放大后显示。
- 隐藏区块不显示流体悬停提示，也不能选中其流体点位。点击保留区块复制该区块中心坐标。
  背景区块网格继续显示。田内最小/最大值仅统计符合条件的区块。
- **Reset filters** 在对话框内恢复全部、最低值 0；点 **OK** 应用，点 **Cancel** 保持原筛选。
  无效数值不会部分应用。更换维度或标点模式会清空名称选择；最低 L/Op 保留，且只影响流体。
  更改筛选复用已加载数据，不重新请求地图。

这里的 L/Op 沿用 Visual Prospecting，表示每次操作的产出，不是地下总可采储量。
按地图当前持有的 `current / initial` 数值筛选，数据来源规则沿用 v39。
`World → Export Coordinates` 中明确标为 `(all)` 的批量导出仍导出所选区域的全部点位。

协议升级为 **20**，请将 `mods` 中旧 Worker 替换为 `amidst-gtnh-worker-v40.jar`，
重启游戏并运行 `amidst-gtnh-biomes-v0-2-v40.jar`。不能与 v39 Worker 混用。
v39 的探矿精度和维度背景限制仍适用，见 [v39 说明](gtnh-v39-prospecting.md)。

验证覆盖：本地化目录传输、缺失目录拒绝、同名 ID 区分、维度内选项、取消和无效输入、
完整 ID 匹配、阈值等号边界、负坐标区块命中，以及模拟地图的低产区块隐藏和高产区块保留。
完整构建同时运行既有测试、真实 GT 流体方法的 7,680 区块对比和 Worker 映射检查。
尚未在完整 GTNH 游戏中实测此版本。
